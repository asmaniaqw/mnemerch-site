# Перенос mnemerch с GitHub Pages на mnemerch.ru — список задач

Документ ведём отдельно от обычных правок сайта. Сюда добавляем всё, что нужно сделать именно перед запуском на основном домене.

## 1. Пути и домен

- [ ] Заменить `<base href="/mnemerch-site/">` на `<base href="/">` во всех HTML-файлах.
- [ ] Проверить, что CSS, JS, изображения, компоненты header/footer и JSON-файлы открываются от корня `https://mnemerch.ru/`.
- [ ] Проверить внутренние ссылки на страницах `p/*.html` и `blog/*.html`.
- [ ] После переноса проверить сайт без GitHub Pages-пути `/mnemerch-site/`.

## 2. SEO

- [ ] Заменить canonical с GitHub Pages на `https://mnemerch.ru/...`.
- [ ] Заменить `og:url` и `og:image` на production-URL.
- [ ] Обновить `sitemap.xml` под `https://mnemerch.ru/`.
- [ ] Обновить `robots.txt`: `Sitemap: https://mnemerch.ru/sitemap.xml`.
- [ ] Закрыть GitHub Pages-версию от индексации после запуска основного домена.
- [ ] Проверить JSON-LD: Organization, WebSite, Product, BreadcrumbList.

## 3. Заявки и backend

- [ ] Поднять endpoint `/api/lead`.
- [ ] Отправлять заявки в Telegram-бот.
- [ ] Дублировать заявки на email.
- [ ] Подключить CRM или таблицу для хранения лидов.
- [ ] Добавить логирование ошибок отправки.
- [ ] Проверить fallback в WhatsApp, если backend недоступен.
- [ ] Убедиться, что сообщение об успехе появляется только после реальной отправки заявки.

## 4. Персональные данные, cookie и кэш

Важно: это технический чеклист, финальную формулировку политики лучше проверить у юриста перед запуском.

- [ ] Проверить, кто является оператором персональных данных: ИП/ООО/самозанятый/другое юрлицо.
- [ ] Внести реквизиты оператора в политику конфиденциальности.
- [ ] Проверить, нужно ли подавать уведомление оператора персональных данных в Роскомнадзор.
- [ ] Оставить checkbox согласия на всех формах заявок.
- [ ] Проверить текст согласия рядом с формами.
- [ ] Описать в политике, какие данные собираются: имя, телефон, Telegram, email, компания, тираж, комментарий.
- [ ] Описать передачу сообщений через WhatsApp/Telegram, если заявки уходят туда.
- [ ] Описать кэш браузера: изображения, CSS, JS и шрифты могут сохраняться браузером для ускорения загрузки.
- [ ] До подключения Яндекс.Метрики, рекламных пикселей, онлайн-чата, CRM-виджета или коллтрекинга описать их в политике.
- [ ] Если подключаем аналитику/пиксели, добавить cookie-уведомление или баннер согласия до запуска этих скриптов.
- [ ] Не запускать рекламные/аналитические скрипты до готовности политики и согласий.

## 5. Аналитика

- [ ] Подключить Яндекс.Метрику после готовности политики и cookie-блока.
- [ ] Настроить цели: отправка формы, клик WhatsApp, клик Telegram, открытие товара, клик “Получить расчёт”.
- [ ] Проверить, что цели не дублируются.

## 6. Финальная проверка перед запуском

- [ ] Проверить формы на desktop и mobile.
- [ ] Проверить WhatsApp-сообщение с заполненными данными.
- [ ] Проверить Telegram/телефон/email в header/footer/contact.
- [ ] Проверить `404` и битые ссылки.
- [ ] Проверить sitemap и robots после загрузки на домен.
- [ ] Проверить мобильные ширины: 360, 375, 390, 414, 430, 768 px.
