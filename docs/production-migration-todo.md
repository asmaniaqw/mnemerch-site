# Перенос mnemerch с GitHub Pages на mnemerch.ru — список задач

Документ ведём отдельно от обычных правок сайта. Сюда добавляем всё, что связано с переносом на основной домен. Если задачу можно сделать сейчас без вреда для GitHub Pages, делаем её сразу и отмечаем как готовую.

## 1. Пути и домен

- [ ] Заменить `<base href="/mnemerch-site/">` на `<base href="/">` во всех HTML-файлах.
- [ ] Проверить, что CSS, JS, изображения, компоненты header/footer и JSON-файлы открываются от корня `https://mnemerch.ru/`.
- [ ] Проверить внутренние ссылки на страницах `p/*.html` и `blog/*.html`.
- [ ] После переноса проверить сайт без GitHub Pages-пути `/mnemerch-site/`.

## 2. SEO

- [ ] Заменить canonical с GitHub Pages на `https://mnemerch.ru/...`.
- [ ] Заменить `og:url` и `og:image` на production-URL.
- [ ] Обновить `sitemap.xml` под `https://mnemerch.ru/`.
- [ ] Обновить `robots.txt`: `Sitemap: https://mnemerch.ru/sitemap.xml`.
- [ ] Закрыть GitHub Pages-версию от индексации после запуска основного домена.
- [ ] Проверить JSON-LD: Organization, WebSite, Product, BreadcrumbList.

- [x] На основных страницах добавлены Open Graph и Twitter Card для превью ссылок.
- [x] На товарных страницах Product schema использует локальные изображения и пояснение про ориентировочную цену без нанесения.
- [x] `sitemap.xml` очищен от удалённых файлов и шаблонов.

## 3. Заявки и backend

- [x] Вынести настройки заявок в `js/site-config.js`, чтобы GitHub Pages был публичным тестовым стендом production-версии, а не отдельной демо-версией.
- [ ] Поднять endpoint `/api/lead`.
- [ ] Отправлять заявки в Telegram-бот.
- [ ] Дублировать заявки на email.
- [ ] Подключить CRM или таблицу для хранения лидов.
- [ ] Добавить логирование ошибок отправки.
- [ ] Проверить fallback в WhatsApp, если backend недоступен.
- [ ] После запуска backend переключить `leadMode` в `js/site-config.js` с `whatsapp` на `api`.
- [ ] Убедиться, что сообщение об успехе появляется только после реальной отправки заявки.

## 4. Персональные данные, cookie и кэш

Важно: это технический чеклист, финальную формулировку политики лучше проверить у юриста перед запуском.

- [ ] Проверить, кто является оператором персональных данных: ИП/ООО/самозанятый/другое юрлицо.
- [ ] Внести реквизиты оператора в политику конфиденциальности.
- [ ] Проверить, нужно ли подавать уведомление оператора персональных данных в Роскомнадзор.
- [x] Оставить checkbox согласия на всех формах заявок.
- [ ] Проверить текст согласия рядом с формами.
- [x] Описать в политике, какие данные собираются: имя, телефон, Telegram, email, компания, срок/дату мероприятия, комментарий.
- [x] Описать передачу сообщений через WhatsApp/Telegram, если заявки уходят туда.
- [x] Описать кэш браузера: изображения, CSS, JS и шрифты могут сохраняться браузером для ускорения загрузки.
- [ ] До подключения Яндекс.Метрики, рекламных пикселей, онлайн-чата, CRM-виджета или коллтрекинга описать их в политике.
- [x] Добавить cookie-уведомление и механизм согласия до запуска необязательных скриптов.
- [x] Не запускать рекламные/аналитические скрипты до согласия: для будущих скриптов использовать `MneConsent.loadScriptWhenAllowed()`.


### Что уже заложено в коде

- `js/privacy-consent.js` показывает уведомление о cookie/данных браузера.
- `js/site-config.js` хранит ключ согласия и режим заявок.
- Выбор пользователя сохраняется в `localStorage` под ключом `mnemerch_cookie_consent_v1`.
- Необязательные скрипты аналитики/маркетинга нужно подключать только через `MneConsent.loadScriptWhenAllowed()`.
- В `privacy.html#cookies` уже описаны cookie, localStorage и кэш браузера.
